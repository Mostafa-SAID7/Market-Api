Data Schema & Entity Dictionary

Relational entity specifications, C# data types, and EF Core 9 Fluent API validation rules

Entity Relationship Overview

Market API enforces a clean, normalized relational schema backed by SQL Server:

  • Products ↔ Categories (Many-to-One: Product belongs to Category)
  • Products ↔ Vendors (Many-to-One: Product is supplied by Vendor)
  • Orders ↔ Users (Many-to-One: Order is placed by Customer User)
  • Carts ↔ Users (One-to-One: Customer active shopping cart)
  • Reviews ↔ Products & Users (Many-to-One rating & review model)

7 Relational Entity Specifications

Product Entity

Table: Products
-----------------------------------------------------------------------
Field         | Type           | Nullable | Validation / Constraints
-----------------------------------------------------------------------
Id            | Guid (PK)      | No       | Primary Key (Sequential Guid)
Name          | string         | No       | Max length 200, Required
Description   | string         | Yes      | Max length 2000
Price         | decimal(18,2)  | No       | Range [0.01 - 1,000,000.00]
Quantity      | int            | No       | Minimum 0
CategoryId    | Guid (FK)      | No       | Foreign Key -> Categories.Id
VendorId      | Guid (FK)      | No       | Foreign Key -> Vendors.Id
Status        | ProductStatus  | No       | Enum (Draft, Active, Archived)
CreatedAt     | DateTime       | No       | UTC Timestamp
