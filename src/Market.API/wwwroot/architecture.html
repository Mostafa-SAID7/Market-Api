Clean Architecture & Design Patterns

Strict 4-layer separation of concerns powered by CQRS, MediatR, and Entity Framework Core 9

4-Layer Dependency Rules

Dependencies point inwards only toward the core Domain layer:

[ Market.API ] Presentation Layer
      ↓ (depends on Application)
[ Market.Application ] Use Cases & CQRS Handlers
      ↓ (depends on Domain)
[ Market.Domain ] Core Entities, Enums & Interfaces (Zero external dependencies)
      ↑ (implements Domain interfaces)
[ Market.Infrastructure ] DbContext, EF Core & Repositories

1. Domain Layer

Project: Market.Domain

  • Core Domain Entities (Product, Order, User, etc.)
  • Value Objects (Slug, Money, Email)
  • Repository Interfaces (IProductRepository)
  • Zero third-party NuGet dependencies

2. Application Layer

Project: Market.Application

  • MediatR Command & Query Handlers
  • DTOs and API Contract Mappings
  • FluentValidation Pipeline Behaviors
  • Orchestrates business workflows

3. Infrastructure Layer

Project: Market.Infrastructure

  • MarketDbContext (EF Core 9)
  • Concrete Repository Implementations
  • SQL Server Fluent API Mappings
  • EF Core Migrations & Seeders

4. API Layer

Project: Market.API

  • Thin Controllers delegating to MediatR
  • Global Exception Handling Middleware
  • OpenAPI / Swagger Documentation
  • Dependency Injection Composition Root

CQRS & Request Lifecycle

1. Client Sends HTTP Request -> GET /api/products/123
2. Controller Delegates -> await _mediator.Send(new GetProductByIdQuery(123))
3. Validation Pipeline -> Runs FluentValidation rules before execution
4. MediatR Dispatches -> GetProductByIdQueryHandler handles query
5. Repository Queries -> IProductRepository reads from SQL Server via EF Core 9
6. Response returned -> Controller returns 200 OK with ProductResponse DTO
