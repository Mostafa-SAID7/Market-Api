API Documentation

Complete guide to the Market API v2.0 with MediatR, Validation, and 7 entities

Getting Started

Market API is a comprehensive RESTful service for managing a complete marketplace with 7 entities. All responses are in JSON format.

Base URL:

http://localhost:5000/api

Entities: Products, Categories, Users, Vendors, Orders, Carts, Reviews

Architecture

Built with modern patterns for clean, maintainable code:

  • MediatR CQRS Pattern
  • Repository Pattern
  • Strong Validation Framework
  • Service Layer with Logging
  • Unit of Work Pattern
  • Dependency Injection

Response Format

All API responses follow standard HTTP status codes:

  • 200 - Success
  • 201 - Created
  • 204 - No Content
  • 400 - Bad Request (validation errors)
  • 404 - Not Found
  • 500 - Server Error

Architecture Overview

Market API v2.0 implements modern patterns for enterprise applications:

MediatR CQRS Pattern

Commands handle mutations (Create, Update, Delete) while Queries handle data retrieval. This separation provides better scalability and testability.

Validation Framework

All entities are validated before persistence. Validation rules include required fields, length constraints, format validation (email, URL, phone), and numeric ranges. Invalid requests return 400 Bad Request with detailed validation errors.

Repository Pattern

Data access is abstracted through repositories and Entity Framework Core 9, making the code testable and database-agnostic. SQL Server is the primary relational database with full async/await support.

Service Layer

Business logic is isolated in services with comprehensive logging for debugging and monitoring. All services use dependency injection and follow SOLID principles.

Request/Response Examples

Here are examples of how to interact with the API:

Get All Products

curl -X GET http://localhost:5000/api/products

Response: 200 OK
[
  {
    "id": "507f1f77bcf86cd799439011",
    "name": "Gaming Laptop",
    "price": 1299.99,
    "category": "Electronics",
    "quantity": 50
  }
]

Create Product (with validation)

curl -X POST http://localhost:5000/api/products \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Gaming Keyboard",
    "description": "Mechanical RGB keyboard",
    "category": "Electronics",
    "vendorId": "507f1f77bcf86cd799439000",
    "price": 149.99,
    "quantity": 30
  }'

Response: 201 Created
{
  "id": "507f1f77bcf86cd799439012",
  "name": "Gaming Keyboard",
  "price": 149.99
}

Create User

curl -X POST http://localhost:5000/api/users \
  -H "Content-Type: application/json" \
  -d '{
    "firstName": "John",
    "lastName": "Doe",
    "email": "john@example.com",
    "phoneNumber": "+1234567890"
  }'

Response: 201 Created

Create Order

curl -X POST http://localhost:5000/api/orders \
  -H "Content-Type: application/json" \
  -d '{
    "customerId": "507f1f77bcf86cd799439001",
    "items": [...],
    "shippingAddress": "123 Main St",
    "shippingCost": 50.00,
    "tax": 100.00
  }'

Response: 201 Created

Validation Error Example

# Missing required fields
curl -X POST http://localhost:5000/api/products \
  -H "Content-Type: application/json" \
  -d '{"name": ""}'

Response: 400 Bad Request
{
  "errors": {
    "name": "Name is required and must be 1-200 characters",
    "price": "Price is required and must be positive",
    "category": "Category is required"
  }
}
